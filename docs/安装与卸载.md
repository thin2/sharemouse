# 安装与卸载（测试版）

应用保留内部标识 de.feschber.LanMouse、程序名 lan-mouse 和既有配置目录，避免升级后生成另一套身份。安装包展示名为 Sharemouse，窗口和系统权限列表仍可能显示 Lan Mouse。源码数据协议为 v7，参与连接的电脑应使用兼容构建；v6 不支持 IP 加入流程。

## 连接设备

1. 主设备点击“显示连接 IP”，进入等待加入状态。
2. 其他设备在“附近的主设备”中找到主设备的电脑名称和 IP，点击“连接”。
   列表为空时，手动输入双方共同网络中的一个主设备 IP，点击“连接主设备”。
3. 核对两端显示的指纹，并在两端确认。第三台同样选择主设备，成员和地址自动同步。
4. 调整屏幕布局，在实际提供键鼠的电脑点击“使用本机”，开始共享。

附近设备列表依赖 UDP 4245 局域网广播。路由器开启 AP/客户端隔离、使用 VPN、
不同子网或防火墙拦截广播时可能看不到主设备，此时用手动输入 IP。
列表只用于填写地址，不代表已验证身份，仍需核对两端指纹。

连接信息重启后保留；“停止配对”只关闭新设备加入，不断开已授权成员。
在主设备撤销成员会同步给其他成员。若在从设备自行撤销授权，它会停止信任该组的后续成员更新。
连接 Windows 热点时，使用主设备的热点网卡地址，通常为 `192.168.137.1`。
多网卡或 VPN 环境可能显示多个候选，地址出现在列表中不代表对端一定可达。
网卡变化后停止配对，再点击“显示连接 IP”刷新列表。
IP 改变后重新对同一主设备执行加入。确认后若网络中断，已批准的成员可能仍保留，可重试加入或在主设备撤销。
原有“手动配置”作为高级入口保留，不需要为正常 IP 加入逐台填写名称或证书。

## Apple Silicon Mac

将 Sharemouse-macos-arm64.zip 解压，把 Sharemouse.app 移到 /Applications 或 ~/Applications，再启动。不要直接在下载目录运行后再移动；自启和 Finder 入口会记录应用位置。移动后重新启动，并重新安装 Finder 入口。

打包脚本使用 ad-hoc 签名，没有 Developer ID 或公证。首次下载可能被 Gatekeeper 拦截，请在系统设置的“隐私与安全性”中按系统提供的方式允许此应用。包内 Info.plist 的 LSMinimumSystemVersion 是所带运行库要求的最大值；系统要求和验收情况应以对应包的发布说明为准。

不同构建环境携带的依赖可能要求不同 macOS 版本。支持较旧系统需用相应部署目标的依赖重新构建并验收。

在“隐私与安全性”授予辅助功能、输入监控权限，完全退出后重启。允许局域网访问。只授予正在安装位置的这份应用。升级后若输入失效，核对权限条目是否仍指向当前应用，必要时移除旧条目后重新授权。未授权时可查看界面，但不能以此判断键鼠共享通过。

默认下次登录时启动并隐藏主窗口。设置中的“登录时自动启动”可关闭；菜单栏可打开窗口、停止共享或退出。关闭窗口保留消息；真正退出清空本次消息。程序只实时同步剪贴板，不记录历史。退出后不会自动重新拉起。

安装 Finder 右键入口（终端执行）：

```sh
"/Applications/Sharemouse.app/Contents/MacOS/lan-mouse" cli integration install
```

Finder 中选择文件或文件夹，使用“快速操作”里的 Send with Sharemouse。若未出现，在系统设置的扩展/服务中启用该快速操作。多选合并为一次设备选择。

升级前先从菜单栏退出，再替换整个应用包。配置、证书与下载文件不在应用包中，会保留。旧版 `clipboard-history` 目录不再读取或写入；升级不会自动删除其中已有资料。

卸载前执行包内脚本，随后将应用移到废纸篓：

```sh
/bin/sh "/Applications/Sharemouse.app/Contents/Resources/uninstall-macos.command"
```

脚本停止后台、移除 Finder 快速操作及登录 LaunchAgent。它保留接收文件、配置、证书及旧版数据。删除身份配置会要求设备重新授权，不是普通升级步骤。

## Windows 11 x64

运行 Sharemouse-windows-x64-setup.exe。按当前用户安装到 LocalAppData 下的 Programs/Sharemouse，不需要管理员权限。安装器为英文，应用支持中英文。可选安装 Explorer 的 Send with Sharemouse 入口及桌面快捷方式。

打包脚本不执行 Authenticode 签名。仅在确认来源和文件散列后运行测试安装器，兼容性以对应构建的验收结果为准。程序包含 GTK、libadwaita 和 VC CRT，不要求测试电脑另装开发工具。

首次启动允许 Windows 防火墙在“专用网络”上通信，按需允许同一子网设备。默认输入 UDP 4242、资料 TLS TCP 4243、配对 TCP 4244（仅“等待加入”期间监听）、附近设备发现 UDP 4245；不需要路由器端口转发。安装器不会自动放开公共网络或修改防火墙规则。

默认下一次登录时隐藏启动。通过托盘打开窗口、停止共享或退出，设置中可关闭自启。Windows 11 的传统右键入口可能位于“显示更多选项”。便携 zip 需完整解压，不能只复制 exe；运行以下命令安装右键入口：

```powershell
& '.\Sharemouse\lan-mouse.exe' cli integration install
```

升级安装器会请求旧进程正常退出，等待释放键鼠，再替换文件。若退出失败会停止安装，让用户从托盘退出后重试。卸载使用系统“已安装的应用”或开始菜单入口，会移除托盘程序、自启值与两处右键注册；配置、证书、旧版数据和收到的文件保留。便携版先关闭自启，再执行 cli integration uninstall，然后退出并删除解压目录。

## 开发机生成包

桌面图标已提供 `app-icon.ico`（Windows 程序与安装器）和 `app-icon.icns`
（macOS 应用包），打包时直接使用，无需安装图片转换工具。
PNG 母版保存在 `assets/icons/app-icon.png`。需要重新生成图标时，
在安装 Pillow 的 Python 环境执行 `python scripts/generate-app-icons.py`。
Windows 应重新编译程序后打包；`-SkipBuild` 不会更新旧 exe 内嵌的图标。

使用仓库固定 Rust 和 Cargo.lock。脚本不自动安装开发依赖，不发布 GitHub Release；输出目录已存在时拒绝覆盖。

Mac 已配置 Rust、GTK4、libadwaita、librsvg、Xcode 命令行工具及 Python 3.11+ 后，在仓库根执行：

```sh
python3 scripts/package-macos.py --offline
```

默认构建 release，输出 target/packages/macos-arm64/Sharemouse-macos-arm64.zip。调试包可加 --debug，已有匹配二进制时才使用 --skip-build。包内 Source 含当前受版本控制的源码、Cargo.lock、依赖来源/许可清单及 build.json；先暂存本轮新增源码，避免漏打包。源码修改未提交时 build.json 会明确标记 modified。

Mac zip 旁的 Sharemouse-macos-arm64.build.json 记录最终签名程序的 binary_sha256 和 zip_sha256。签名会改变程序字节，因此包内清单只记录 pre_sign_binary_sha256，不能拿它与最终程序直接比较。可用 shasum -a 256 核对 zip 和解压后的程序。

Windows 在已配置 MSVC x64 开发终端、PowerShell 7、固定 Rust、gvsbuild GTK/libadwaita/librsvg、Python 3.11+ 和 Inno Setup 6 的开发机执行：

```powershell
$env:PKG_CONFIG = 'C:\gtk-build\gtk\x64\release\bin\pkgconf.exe'
$env:PATH = "C:\gtk-build\gtk\x64\release\bin;$env:PATH"
.\scripts\package-windows.ps1 `
  -GtkPrefix 'C:\gtk-build\gtk\x64\release' `
  -VcRedistDir $env:VCToolsRedistDir -Offline
```

VcRedistDir 指向 Visual Studio VC/Redist/MSVC 的具体版本目录，其中有 x64/Microsoft.VC*.CRT。未配置时显式传路径。脚本检查 DLL 依赖、复制 schemas/图标/图像加载器/运行库和许可证，输出安装 exe 与完整便携 zip。-PortableOnly 可仅生成便携包。不要混用 GNU Rust 与 MSVC GTK 构建。

发布安装包前应完成目标系统验收和依赖许可核对，并明确标注签名、公证与测试状态。

不在本地配置 Windows 开发环境时，可在仓库 GitHub Actions 中选择 Test packages → Run workflow，完成后下载 Sharemouse-windows-x64 artifact 内的安装器/便携包。构建失败时先按日志修复；构建成功不等于实机验收通过。它只上传测试 artifact。
